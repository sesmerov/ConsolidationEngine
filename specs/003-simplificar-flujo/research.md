# Investigación y decisiones de diseño

Iteración 003, 6 de noviembre de 2026. Se contrastaron los 17 requisitos con el código del checkout y con la [prueba FINREP ejecutada durante la especificación](evidencia.md). Las decisiones siguientes guían la implementación.

| Decisión | Motivo comprobado en el proyecto | Alternativa considerada |
| --- | --- | --- |
| Retirar el recorrido anterior de Cargar y mantener el importador de compatibilidad. | La retirada aprobada incluye la casilla, la plantilla descargable y los dos archivos e instrucciones del ejemplo anterior. Las demos visuales COREP y tipada utilizan un flujo distinto de inspección y publicación. | Renombrar el bloque «Otros formatos» conservaría el recorrido que Diego pidió retirar. |
| Usar ayuda expandible con un botón etiquetado, contenido seleccionable y cierre con retorno de foco. | La huella se debe poder copiar y las explicaciones ocupan varios párrafos. Cobertura, exclusiones por aceptar, caducidad accionable y errores permanecen junto a la operación. | Un tooltip dependiente del puntero dificulta leer y copiar desde teclado o pantalla táctil. [Patrón de apertura y cierre, W3C](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) |
| Actualizar el código al escribir, con una pausa de 250 ms y una generación de consulta por conjunto, versión y filtros. | La ruta de reglas ya busca subcadenas sin distinguir mayúsculas y vincula el cursor a los filtros. Los controles están dentro de la condición que monta la página de resultados. Separar su ciclo de vida conserva el foco incluso con cero coincidencias. | Filtrar las 50 filas cargadas oculta coincidencias del resto del catálogo. Solo retrasar las peticiones deja una ventana en la que una respuesta anterior podría ganar. La generación se invalida al escribir. La cancelación del transporte puede ahorrar trabajo si el cliente la admite. [Comportamiento de HttpClient](https://angular.dev/guide/http/making-requests) |
| Preparar en la API una revisión temporal de destinos para una ejecución completa y una base vigente. | La ruta de resultados calcula política y lados por página. El guardado actual sustituye toda la configuración. Puede haber hasta un millón de instancias con un límite de cuerpo JSON de 1 MiB. Un trabajo acotado clasifica el conjunto completo una vez. La interfaz recibe páginas y envía cambios pequeños. | Recorrer todas las páginas desde el navegador o enviar todas las sugerencias al guardar multiplica las lecturas y puede superar el límite de transporte. Un borrador construido solo con las filas visitadas perdería destinos y conflictos fuera de pantalla. [Ruta actual de resultados](../../apps/api/src/routes/results.ts) · [Servicio de direcciones](../../apps/api/src/recalculation/directions-service.ts) |
| Distinguir datos recién importados, decisiones revisadas y configuraciones históricas sin marca de revisión. | El estado actual guarda las direcciones elegidas. Un listado vacío puede significar una importación reciente o que alguien las quitó todas. El plan añade metadatos versionados para reconocer las omisiones futuras y conservar las elecciones anteriores. | Interpretar cada ausencia como consentimiento para activar una sugerencia reintroduciría destinos que el analista pudo haber excluido. |
| Separar deducción de lado, elección del productor y aprobación de cambios. | La política del motor clasifica expresión, precondición y tipos. Se reutiliza la resolución de ambas direcciones por instancia. Si la comprobación de un lado es inconclusa por cuota o plazo, la instancia queda indeterminada. Dos productores pueden tener la misma coordenada completa incluso cuando cada lado es inequívoco. | La heurística de contar referencias en el texto, elegir la primera fila o preferir un código EBA puede producir otro importe. El guardado confirma la configuración. La simulación sigue usando Kahn y la aplicación exige selección, cierre de dependencias y aceptación. |
| Señalar el siguiente paso al confirmar la publicación, en el store del conjunto. | La carga inspeccionada aún puede descartarse. Guardar direcciones cambia la versión. La descarga posterior a aplicar debe usar la versión del recibo aunque el selector histórico muestre otra. | Derivar el hito de un clic, de cualquier trabajo terminado o del último número de versión causaría recomendaciones prematuras o incorrectas. El indicador estático con texto mantiene el foco en la acción actual. |
| Contar los identificadores seleccionados en toda la simulación para mostrar la confirmación. | El total global existe en PreviewStore antes de recibir el cálculo asíncrono de dependencias. ApplyStore mantiene la aceptación ligada a la selección y conserva los datos de un intento incierto. | Derivar la visibilidad de las filas actuales o del último cierre recibido ocultaría el panel al cambiar de página o al seleccionar la primera propuesta. Desmontar el estado junto con el panel podría perder el reintento o conservar una aceptación anterior. [Store de aplicación](../../apps/web/src/app/recalculation/apply.store.ts) |
| Usar la lista de contextos vigentes y la selección que ya mantiene SessionStore. | El store conserva el contextId si aún existe. Con uno, la cabecera puede presentar entidad, fecha y módulo una sola vez. Con varios, se elige por identidad y se muestra una etiqueta humana distinguible. | Un selector deshabilitado para una opción ocupa espacio y sugiere una acción. Contar archivos, módulos o versiones en vez de contextos produciría controles incorrectos. [Store de sesión](../../apps/web/src/app/core/session.store.ts) |
| Servir el mismo símbolo local en cabecera y favicon, con una portada genérica legible en la respuesta HTML inicial. | El documento actual contiene título, idioma y viewport. Angular puede empaquetar un activo estático y Fastify ya sirve el build. La portada anónima puede verificarse localmente incluso con un conjunto sintético activo. | Añadir render del servidor, dependencias gráficas externas o un despliegue público excede el objetivo. Google requiere acceso a la portada y al favicon para el rastreo público. [Portada actual](../../apps/web/src/index.html) · [Favicon](https://developers.google.com/search/docs/appearance/favicon-in-search) · [Acceso del rastreador](https://developers.google.com/search/docs/essentials/technical) |
| Reutilizar la prueba FINREP y adaptar la preparación de datos de las regresiones que usaban el control anterior. | El extracto F_01.01 falla en el reconocimiento visual, mientras las cuatro coordenadas en el formato anterior permiten verificar ambas reglas. Parte de la batería de navegador y el benchmark 002 abren deliberadamente la carga anterior. | Introducir un interruptor de pruebas en el producto devolvería a la interfaz el recorrido retirado. Las pruebas de compatibilidad pueden preparar su conjunto por la API en un proceso propio y continuar por la interfaz real. Un protocolo de rendimiento con distinta preparación debe identificarse por separado. |

Las decisiones de alcance quedan cerradas para diseñar los contratos. Colocar los archivos antes de las demos y retirar el progreso terminado permanecen como propuestas de la fase anterior. Los controles de confirmación y de contexto sí integran el alcance aprobado.
